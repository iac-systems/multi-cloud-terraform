# Terraform State Management & Recovery Guide

This project uses a single S3 bucket for multi-environment state storage with strict isolation and security controls.

## 1. State File Path Structure
The state files are stored in the S3 bucket `isre-devops-terraform-state-139337686739` in the `us-west-1` region. The paths are dynamically generated by Terragrunt based on the folder structure.

| Environment | Resource | S3 Path (Key) |
| :--- | :--- | :--- |
| **Dev** | VPC | `live/aws/dev/vpc/terraform.tfstate` |
| **Dev** | EKS | `live/aws/dev/eks/terraform.tfstate` |
| **Stg** | VPC | `live/aws/stg/vpc/terraform.tfstate` |
| **Prod** | VPC | `live/aws/prod/vpc/terraform.tfstate` |

---

## 2. Security Controls
- **Versioning**: Enabled on the bucket to allow point-in-time recovery.
- **MFA-Delete**: Enforced via bucket policy. Deletion requires an MFA-authenticated session.
- **Locking**: Handled via S3 native locking (or DynamoDB if configured) to prevent concurrent writes.

## 3. Recovery Procedures

### Scenario A: State Corruption (e.g., "Failed to load state")
If a state file becomes corrupted during an apply, you can revert to the previous version.

1. **Identify the corrupted resource**:
   Find the directory (e.g., `live/aws/dev/vpc`).
2. **List versions in S3**:
   ```bash
   aws s3api list-object-versions \
     --bucket isre-devops-terraform-state-139337686739 \
     --prefix live/aws/dev/vpc/terraform.tfstate
   ```
3. **Download the last known good version**:
   Identify the `VersionId` of the previous version and download it:
   ```bash
   aws s3api get-object \
     --bucket isre-devops-terraform-state-139337686739 \
     --key live/aws/dev/vpc/terraform.tfstate \
     --version-id <GOOD_VERSION_ID> \
     recovered_state.json
   ```
4. **Push the recovered state**:
   ```bash
   # Caution: This overwrites the current state in S3
   aws s3 cp recovered_state.json s3://isre-devops-terraform-state-139337686739/live/aws/dev/vpc/terraform.tfstate
   ```

### Scenario B: Accidental Deletion
If a state file is deleted, S3 creates a "Delete Marker".

1. **Find the Delete Marker**:
   ```bash
   aws s3api list-object-versions \
     --bucket isre-devops-terraform-state-139337686739 \
     --prefix live/aws/dev/vpc/terraform.tfstate
   ```
2. **Remove the Delete Marker**:
   Deleting the Delete Marker will "undelete" the previous version.
   ```bash
   aws s3api delete-object \
     --bucket isre-devops-terraform-state-139337686739 \
     --key live/aws/dev/vpc/terraform.tfstate \
     --version-id <DELETE_MARKER_VERSION_ID>
   ```

### Scenario C: Complete Manual Override
If the CLI recovery fails, you can use the AWS Console:
1. Navigate to the S3 Bucket.
2. Select the `terraform.tfstate` object.
3. Click "Show versions".
4. Delete the top-most (corrupted/delete marker) version to restore the one beneath it.
